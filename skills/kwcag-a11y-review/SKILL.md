# KWCAG 2.2 접근성 검수

웹 화면 코드를 KWCAG 2.2 검사항목 기준으로 검수한다. 결과는 "고칠 수 있는 목록"이어야 하므로, 모든 발견 사항에 항목 번호, 위치, 수정안, 판정 유형을 붙인다.

## 지켜야 할 원칙

- **판정 유형을 항상 구분해서 표시한다.**
  - 자동: 코드나 도구 결과만으로 확정됨
  - AI: 코드를 읽고 판단했지만 사람 확인이 필요함
  - 수동: 화면·키보드·스크린리더로 직접 확인해야 함
  AI 판단을 자동 판정처럼 쓰지 않는다. 검수 결과를 읽는 사람이 무엇을 믿고 무엇을 다시 봐야 하는지 알아야 하기 때문이다.
- **"준수", "통과", "인증 가능"이라고 단정하지 않는다.** 자동 스캔은 33개 항목 중 일부만 판정할 수 있고, 위반 0건은 준수를 뜻하지 않는다. 최종 판정은 사람이 한다고 명시한다.
- **기준 문구와 수치는 references 문서의 요약을 따르되, 원문 확인이 필요하다고 표시된 수치(명도 대비, 컨트롤 크기 등)는 보고서에도 그렇게 적는다.**
- **위치는 `파일경로:라인` 형식으로 쓴다.** 런타임 스캔 결과는 URL과 CSS 선택자로 쓴다.
- **사용자가 요청하기 전에는 코드를 고치지 않는다.** 수정을 요청받으면 고친 뒤 같은 검사를 다시 돌려 전후를 기록한다.
- **프로젝트 설정(package.json 등)을 바꾸는 설치는 사용자에게 먼저 묻는다.**

## 절차

### 1. 범위 확정

- 검수 대상(파일, 컴포넌트, 라우트, URL)을 정한다. 지정이 없으면 사용자에게 화면 단위로 묻거나, 주요 진입 화면부터 제안한다.
- `package.json`으로 프레임워크와 UI 라이브러리(Next.js, React, Vue, Tailwind, Radix/shadcn 등)를 확인한다.

### 2. 체크리스트 로드

`references/kwcag-2.2-checklist.md`를 읽는다. 33개 항목별 기준 요약, 코드에서 볼 것, 판정 유형, 관련 axe 규칙이 들어 있다.

### 3. 정적 코드 검토 (AI)

먼저 아래 패턴으로 의심 지점을 빠르게 찾고, 걸린 파일은 반드시 맥락을 읽고 판단한다. 패턴에 걸렸다고 위반으로 쓰지 않는다.

| 찾을 것 | 예시 패턴 | 항목 |
|---|---|---|
| alt 없는 이미지, 무의미한 alt | `<img`, `<Image`, `alt="image"`, `alt="icon"` | 1.1.1 |
| 비대화형 요소의 클릭 핸들러 | `<div onClick`, `<span onClick`, `<li onClick` | 2.1.1 |
| 마우스 전용 이벤트 | `onMouseEnter`, `onMouseOver` (키보드 대응 없음) | 2.1.1 |
| 초점 표시 제거 | `outline-none`, `outline: none`, `focus:outline-none` (`focus-visible:` 대체 없음) | 2.1.2 |
| 양수 tabIndex | `tabIndex={1}` 이상 | 2.1.2 |
| 레이블 없는 입력 | `placeholder=`만 있고 `<label>`/`aria-label` 없음 | 3.3.2 |
| 소리 자동 재생 | `autoPlay`(muted 없음), `autoplay` | 1.4.2 |
| 자동 롤링 | Swiper·캐러셀 `autoplay`, `setInterval` | 2.2.2 |
| down 이벤트 실행 | `onMouseDown`, `onPointerDown`, `onTouchStart` | 2.5.2 |
| 단일 문자 단축키 | `keydown` 리스너에서 수정키 없이 `e.key === 'k'` 등 | 2.1.4 |
| 새 창·의도치 않은 이동 | `target="_blank"`, `window.open`, `<select onChange={...navigate}>` | 2.4.3, 3.2.1 |
| 붙여넣기 차단 | `onPaste` + `preventDefault` | 3.3.3 |
| 고정 id의 반복 렌더링 | 목록 컴포넌트 안의 `id="..."` 리터럴 | 4.1.1 |
| 커스텀 위젯 상태 | `role="tab"`, `role="dialog"`, 드롭다운, 토글 | 4.2.1 |
| 기본 언어 | `<html lang`, `app/layout.tsx` | 3.1.1 |
| 페이지 제목 | `metadata`, `generateMetadata`, `<title>`, `document.title` | 2.4.2 |
| 기기 동작 | `devicemotion`, `deviceorientation` | 2.5.4 |

React·Next.js·Tailwind에서 자주 놓치는 것:
- 아이콘 버튼에 `sr-only` 텍스트나 `aria-label`이 없는 경우
- Radix/shadcn 컴포넌트를 커스터마이징하면서 `DialogTitle`을 지우거나 `asChild`로 감싼 요소가 버튼이 아니게 된 경우
- SPA 라우트 이동 후 페이지 제목이 그대로이거나 초점이 이전 위치에 남는 경우
- portal로 렌더링한 모달이 초점 이동·복귀를 하지 않는 경우
- 디자인 토큰의 회색 텍스트 대비가 부족한 경우 (토큰 값으로 대비를 직접 계산해 수치로 적는다)

### 4. 자동 스캔 (가능할 때)

`scripts/kwcag-scan.mjs`는 axe-core 결과를 KWCAG 항목별로 묶어 Markdown 보고서로 만든다. 검수 대상 프로젝트 루트에서 실행한다. 필요한 패키지가 없으면 스크립트가 lockfile(pnpm/yarn/bun/npm)에 맞는 설치 명령을 알려 준다 — 설치는 사용자에게 먼저 묻는다.

- 렌더링된 페이지 (권장): 개발 서버가 떠 있고 `playwright`, `@axe-core/playwright`가 설치돼 있을 때
  ```bash
  node <skill-dir>/scripts/kwcag-scan.mjs --url http://localhost:3000 --url http://localhost:3000/login --keyboard --out a11y-scan.md
  ```
- 정적 HTML: 빌드 결과물이나 마크업 파일만 있을 때 (`jsdom`, `axe-core` 필요)
  ```bash
  node <skill-dir>/scripts/kwcag-scan.mjs --file out/index.html --out a11y-scan.md
  ```
- `--experimental`을 붙이면 2.5.3(`label-content-name-mismatch`) 같은 실험 규칙도 돈다. `--json`으로 원자료도 저장할 수 있다.
- `--keyboard`(URL 모드 전용)를 붙이면 실제로 Tab을 눌러 키보드 확인을 한다. 렌더링 스캔에는 기본으로 붙인다.
  - 2.1.2 위반: 보이지 않는 요소가 초점을 받음 / 검토 필요: 초점 전후 겉모양이 같음
  - 2.1.1 위반: 초점이 일부 요소 사이에서만 돎(키보드 함정) / 검토 필요: `cursor: pointer`인데 초점을 못 받는 요소(`<div onClick>` 후보)
  - 보고서에 "키보드 초점 순서" 목록이 붙는다. 화면 순서와 맞는지는 사람이 판단하므로 1.3.2·2.1.2 수동 확인 항목으로 옮긴다.
  - 한계: Tab 순회만 본다. 모달 열기·Esc 닫기·초점 복귀처럼 조작이 필요한 흐름, Enter/Space 동작, 화면 순서와의 일치는 확인하지 않는다. 초점 표시 판정은 요소 자체의 스타일만 비교하므로 부모나 가상 요소로 표시하는 경우는 "표시 없음"으로 잘못 나올 수 있다.

알려진 한계 (보고서에 반영할 것):
- 정적 모드(jsdom)는 레이아웃을 계산하지 못해 명도 대비(1.4.3), 일부 랜드마크·제목 규칙을 판정하지 못한다. 스크립트가 "계산하지 못한 규칙"으로 따로 알려 준다.
- axe는 placeholder만 있는 입력을 레이블이 있는 것으로 통과시킨다. KWCAG 3.3.2 관점에서는 정적 검토로 따로 확인한다.
- axe 최신 버전에서 `duplicate-id` 규칙은 기본 비활성이라, 스크립트가 id 중복을 직접 세서 4.1.1로 보고한다.
- `<div onClick>` 같은 키보드 미지원(2.1.1), 제목 셀 없는 표(1.3.1)는 axe가 대부분 잡지 못한다. 정적 검토가 필수다.
- "관련 규칙(참고)"으로 표시된 결과(region, landmark 등)는 KWCAG 직접 위반이 아니라 개선 권고로 다룬다.
- "미분류(KWCAG 직접 대응 없음)"로 묶인 결과(`meta-viewport`, `css-orientation-lock` 등 WCAG 전용 규칙)도 개선 권고로만 다룬다.
- 스캔에 실패한 URL은 보고서 상단 "검사하지 못한 대상"에 남고 종료 코드가 4가 된다. 보고서의 "한계"에 옮겨 적는다.

### 5. 수동 확인 목록 만들기

자동·AI로 판정할 수 없는 항목은 대상 화면에 맞춘 구체적인 확인 절차로 바꿔 적는다. 일반론이 아니라 "이 화면에서 무엇을 어떻게 할지"를 쓴다. `--keyboard`로 이미 확인한 것(Tab 순회, 숨은 요소 초점, 키보드 함정)은 다시 시키지 말고, 남은 조작 흐름(모달 열고 닫기, 초점 복귀, Enter/Space 동작)과 초점 순서 목록 검토만 남긴다.

예:
- 2.1.1 / 2.1.2: 마우스 없이 Tab·Shift+Tab만으로 헤더 → 필터 → 목록 → 상세 이동, 초점 표시가 항상 보이는지, 모달을 열고 Esc로 닫았을 때 초점이 열기 버튼으로 돌아오는지
- 1.3.2 / 4.2.1: VoiceOver(macOS/iOS) 또는 NVDA로 화면을 처음부터 읽어 순서와 버튼·탭 상태 낭독 확인
- 1.4.1: 흑백(그레이스케일) 보기에서 오류·선택 상태가 구분되는지
- 2.3.1: 애니메이션 주기 확인

### 6. 보고서 작성

아래 형식으로 작성한다. 사용자가 다른 형식을 원하면 따른다.

```markdown
# 접근성 검수 결과 — <대상>

- 기준: KWCAG 2.2 (33개 검사항목)
- 범위: <파일·라우트·URL>
- 방법: 정적 코드 검토 / 자동 스캔(<url|file> 모드, axe-core <버전>) / 수동 확인 목록
- 이 보고서는 준수 여부를 확정하지 않습니다. "AI"와 "수동" 표시 항목은 사람의 확인이 필요합니다.

## 요약
| 항목 | 이름 | 발견 | 판정 유형 | 우선순위 |
|---|---|---|---|---|

## 발견 사항
### 2.1.1 키보드 사용 보장 — `src/features/post/ui/PostCard.tsx:42` (AI)
- 문제: 카드 전체가 `<div onClick>`이라 키보드로 상세 화면에 들어갈 수 없음
- 수정안:
  ```tsx
  // before
  <div onClick={() => router.push(href)}>...</div>
  // after
  <Link href={href} className="block focus-visible:ring-2">...</Link>
  ```

## 수동 확인 필요
- [ ] <화면 맞춤 확인 절차>

## 해당 없음
- 2.4.4 고정된 참조 위치 정보 — 전자출판 형식 아님

## 한계
- <정적 모드 미판정 규칙, 확인하지 못한 화면 등>
```

우선순위는 사용자가 기능을 아예 쓸 수 없게 만드는 문제(키보드 접근 불가, 이름 없는 버튼, 레이블 없는 입력)를 먼저 두고, 정보 손실(대체 텍스트, 명도 대비), 개선 권고 순으로 둔다.

### 7. 수정과 재검사 (요청 시)

- 사용자가 고쳐 달라고 하면 우선순위 순으로 고친다.
- 고친 뒤 3·4단계를 같은 범위로 다시 실행하고, 보고서 끝에 전후 비교(항목별 발견 수)를 붙인다.
