# KWCAG 2.2 검사항목 체크리스트 (코드 검수용)

한국형 웹 콘텐츠 접근성 지침 2.2(2022 개편, 4개 원칙 · 14개 지침 · 33개 검사항목)을
프론트엔드 코드 검수 관점으로 정리한 문서입니다.

- 각 항목의 "기준"은 원문을 요약한 것이며 원문 문장이 아닙니다. 판정 근거로 인용할 때는 공식 원문을 확인하세요.
- 수치 기준(명도 대비, 컨트롤 크기 등)은 최종 판정 전에 공식 원문과 다시 대조하세요.
- "판정" 표기
  - **자동**: 코드나 도구 결과만으로 위반 여부를 확정할 수 있음
  - **AI**: 코드를 읽고 위반 가능성을 판단할 수 있지만, 사람의 확인이 있어야 확정됨
  - **수동**: 실제 화면, 키보드, 스크린리더로 직접 확인해야 함
- "axe"는 axe-core 규칙 중 이 항목과 관련된 것입니다. axe 결과가 없다고 해서 항목을 통과한 것은 아닙니다.

## 1. 인식의 용이성

### 1.1 대체 텍스트

#### 1.1.1 적절한 대체 텍스트 제공
- 기준: 텍스트가 아닌 콘텐츠에는 그 의미나 용도를 이해할 수 있는 대체 텍스트를 제공한다.
- 코드에서 볼 것
  - `<img>`, Next.js `<Image>`의 `alt` 누락
  - alt에 파일명, "이미지", "사진", "icon" 같은 무의미한 값
  - 장식용 이미지는 `alt=""`로 비웠는지 (스크린리더가 건너뛰도록)
  - 아이콘만 있는 버튼·링크에 `aria-label` 또는 숨김 텍스트가 있는지
  - 인라인 `<svg>`가 의미를 가지면 `role="img"` + `aria-label`/`<title>`, 장식이면 `aria-hidden="true"`
  - CSS `background-image`로 의미 있는 정보를 전달하고 있는지
  - 차트·그래프는 핵심 수치를 텍스트로도 제공하는지
- 판정: 유무는 자동 / 내용의 적절성은 AI / 복잡한 이미지 설명의 충분성은 수동
- axe: `image-alt`, `input-image-alt`, `area-alt`, `role-img-alt`, `svg-img-alt`, `object-alt`, `image-redundant-alt`

### 1.2 멀티미디어 대체 수단

#### 1.2.1 자막 제공
- 기준: 멀티미디어 콘텐츠에는 자막, 대본 또는 수어를 제공한다.
- 코드에서 볼 것
  - `<video>`에 `<track kind="captions">`가 있는지
  - 외부 플레이어(YouTube 등) 임베드 시 자막 제공 여부
  - 음성 정보가 없는 영상은 해당 없음으로 기록
- 판정: track 유무는 자동 / 자막 내용의 정확성·동기화는 수동
- axe: `video-caption`, `audio-caption`

### 1.3 적응성

#### 1.3.1 표의 구성
- 기준: 표는 이해하기 쉽게 구성한다 (제목, 제목 셀과 데이터 셀의 구분 등).
- 코드에서 볼 것
  - 데이터 표에 `<caption>` 또는 표 제목이 있는지
  - 제목 셀이 `<th>`이고, 필요하면 `scope`가 있는지
  - 레이아웃 목적으로 `<table>`을 쓰고 있는지
  - div 그리드로 만든 표(가상 스크롤 테이블 등)에 `role="table"/"row"/"columnheader"/"cell"` 또는 `grid` 계열 역할이 있는지
- 판정: 구조는 자동 / 제목의 적절성은 AI
- axe: `td-headers-attr`, `th-has-data-cells`, `td-has-header`, `scope-attr-valid`, `table-duplicate-name`, `table-fake-caption`, `empty-table-header`

#### 1.3.2 콘텐츠의 선형구조
- 기준: 콘텐츠는 논리적인 순서로 제공한다.
- 코드에서 볼 것
  - DOM 순서와 화면에 보이는 순서가 다른 곳: CSS `order`, `flex-direction: *-reverse`, `grid-area` 재배치, `position: absolute`로 옮긴 요소
  - 모달·드롭다운이 문서 끝(portal)에 렌더링될 때 초점과 읽기 순서가 이어지는지
  - 탭 UI에서 탭 목록과 패널의 순서
- 판정: 코드상 의심 지점은 AI / 실제 읽기 순서는 수동 (스크린리더, CSS 끄고 확인)
- axe: 직접 대응 없음

#### 1.3.3 명확한 지시사항 제공
- 기준: 지시사항은 모양, 크기, 위치, 방향, 색, 소리 등에 관계없이 인식될 수 있어야 한다.
- 코드에서 볼 것
  - "오른쪽 버튼을 누르세요", "빨간색으로 표시된 항목", "동그란 아이콘" 같은 안내 문구
  - 같은 안내를 텍스트 레이블이나 이름으로도 전달하는지
- 판정: AI
- axe: 직접 대응 없음

### 1.4 명료성

#### 1.4.1 색에 무관한 콘텐츠 인식
- 기준: 콘텐츠는 색에 관계없이 인식될 수 있어야 한다.
- 코드에서 볼 것
  - 입력 오류를 빨간 테두리로만 표시하는지 (텍스트 메시지, 아이콘 병행 여부)
  - 본문 속 링크의 밑줄을 없애고 색으로만 구분하는지
  - 차트·범례·상태 배지가 색으로만 구분되는지
  - 선택 상태를 색으로만 표시하는지
- 판정: AI / 최종 확인은 수동 (흑백 모드로 보기)
- axe: `link-in-text-block`

#### 1.4.2 자동 재생 금지
- 기준: 소리는 자동으로 재생되지 않아야 한다.
- 코드에서 볼 것
  - `<video autoPlay>`에 `muted`가 없는지, `<audio autoplay>`
  - 페이지 진입 시 소리를 재생하는 스크립트
- 판정: 속성은 자동 / 스크립트 재생은 AI
- axe: `no-autoplay-audio`

#### 1.4.3 텍스트 콘텐츠의 명도 대비
- 기준: 텍스트와 배경의 명도 대비는 4.5 대 1 이상 (큰 텍스트는 3 대 1 이상). 수치는 원문으로 재확인.
- 코드에서 볼 것
  - 연한 회색 텍스트 (예: Tailwind `text-gray-400` on `bg-white`), placeholder 색, 이미지 위 텍스트
  - 디자인 토큰 값으로 대비를 계산할 수 있으면 직접 계산해 수치를 적는다
- 판정: 렌더링된 페이지 스캔은 자동 / 정적 HTML·토큰 기반 추정은 AI
- axe: `color-contrast` (jsdom 정적 스캔에서는 계산되지 않음)

#### 1.4.4 콘텐츠 간의 구분
- 기준: 이웃한 콘텐츠는 구별될 수 있어야 한다 (테두리, 구분선, 간격, 명도 대비 등).
- 코드에서 볼 것
  - 카드·목록 항목 사이 구분선이나 간격이 없는지
  - 영역 경계가 아주 옅은 색 차이로만 구분되는지
- 판정: AI / 수동
- axe: 직접 대응 없음

## 2. 운용의 용이성

### 2.1 입력장치 접근성

#### 2.1.1 키보드 사용 보장
- 기준: 모든 기능은 키보드만으로도 사용할 수 있어야 한다.
- 코드에서 볼 것
  - `<div onClick>`, `<span onClick>`처럼 상호작용 요소가 아닌 태그에 클릭만 붙인 경우 (`role`, `tabIndex={0}`, `onKeyDown`(Enter/Space) 없이)
  - `onMouseOver`/`onMouseEnter`로만 열리는 메뉴·툴팁
  - 드래그로만 가능한 정렬, 슬라이더
  - 스크롤 영역에 키보드로 초점이 갈 수 있는지
  - 초점이 빠져나오지 못하는 영역(키보드 트랩)
- 판정: 정적 탐지는 AI (탐지력 높음) / 실제 Tab 이동은 수동
- axe: `scrollable-region-focusable`, `frame-focusable-content`, `server-side-image-map`

#### 2.1.2 초점 이동과 표시
- 기준: 키보드 초점은 논리적으로 이동하고, 시각적으로 구별할 수 있어야 한다.
- 코드에서 볼 것
  - `outline: none`, Tailwind `outline-none`, `focus:outline-none`을 쓰고 `focus-visible:` 대체 스타일이 없는 경우
  - `tabIndex`에 양수 값
  - 모달이 열릴 때 초점이 모달로 이동하고, 닫힐 때 원래 위치로 돌아오는지
  - 라우트 이동 후 초점 위치
- 판정: 스타일·tabIndex는 AI / 초점 흐름은 수동
- axe: `tabindex`, `focus-order-semantics`(실험)

#### 2.1.3 조작 가능
- 기준: 사용자 입력과 컨트롤은 조작 가능하도록 충분한 크기와 간격으로 제공한다. 크기 수치는 원문으로 재확인.
- 코드에서 볼 것
  - 아이콘 버튼, 닫기 버튼, 체크박스의 실제 터치 영역 크기
  - 인접 컨트롤 사이 간격
- 판정: 렌더링 스캔은 자동(참고) / 수동
- axe: `target-size` (WCAG 2.2 기준 24px이므로 KWCAG 기준과 다를 수 있음, 참고용)

#### 2.1.4 문자 단축키
- 기준: 문자 하나로 작동하는 단축키는 끄거나, 바꾸거나, 해당 컴포넌트에 초점이 있을 때만 작동해야 한다.
- 코드에서 볼 것
  - `keydown` 리스너에서 수정키(Ctrl/Alt/Meta) 없이 단일 문자로 기능을 실행하는 코드
- 판정: AI
- axe: `accesskeys` (참고)

### 2.2 충분한 시간 제공

#### 2.2.1 응답시간 조절
- 기준: 시간 제한이 있는 콘텐츠는 응답시간을 조절할 수 있어야 한다.
- 코드에서 볼 것
  - 세션 만료, 자동 로그아웃 전에 연장 안내가 있는지
  - 인증번호 입력 제한시간의 연장 방법
  - `<meta http-equiv="refresh">`, 일정 시간 뒤 자동 이동
- 판정: AI / 수동
- axe: `meta-refresh`, `meta-refresh-no-exceptions`

#### 2.2.2 정지 기능 제공
- 기준: 자동으로 변경되는 콘텐츠는 움직임을 제어할 수 있어야 한다.
- 코드에서 볼 것
  - 자동 롤링 배너·캐러셀(Swiper `autoplay` 등)에 정지/재생 버튼이 있는지
  - 이전·다음 이동 수단
  - `setInterval`로 바뀌는 공지·티커
- 판정: AI
- axe: `marquee`, `blink`

### 2.3 광과민성 발작 예방

#### 2.3.1 깜빡임과 번쩍임 사용 제한
- 기준: 초당 3~50회 주기로 깜빡이거나 번쩍이는 콘텐츠를 제공하지 않는다.
- 코드에서 볼 것
  - 짧은 주기의 CSS `animation`, 깜빡이는 GIF·영상
- 판정: 의심 지점은 AI / 확정은 수동
- axe: 직접 대응 없음

### 2.4 쉬운 내비게이션

#### 2.4.1 반복 영역 건너뛰기
- 기준: 콘텐츠의 반복되는 영역은 건너뛸 수 있어야 한다.
- 코드에서 볼 것
  - 본문 바로가기(skip link)가 있고, 대상(`#main` 등)이 실제로 존재하는지
  - `<main>`, `<nav>`, `<header>`, `<footer>` 랜드마크 사용
- 판정: 자동 / AI
- axe: `bypass`, `skip-link`, `region`·`landmark-*`(참고)

#### 2.4.2 제목 제공
- 기준: 페이지, 프레임, 콘텐츠 블록에는 적절한 제목을 제공한다.
- 코드에서 볼 것
  - 페이지마다 고유한 `<title>` (Next.js `metadata`/`generateMetadata`, SPA 라우트 변경 시 title 갱신)
  - `<iframe title>`
  - 콘텐츠 블록의 제목(`h1`~`h6`) 구조, 빈 제목, 단계 건너뛰기
- 판정: 유무는 자동 / 적절성은 AI
- axe: `document-title`, `frame-title`, `frame-title-unique`, `page-has-heading-one`, `empty-heading`, `heading-order`, `p-as-heading`(참고)

#### 2.4.3 적절한 링크 텍스트
- 기준: 링크 텍스트는 용도나 목적을 이해할 수 있도록 제공한다.
- 코드에서 볼 것
  - "더보기", "여기", "클릭" 단독 링크 (맥락 없이)
  - 아이콘만 있는 링크의 이름
  - 새 창으로 열리는 링크(`target="_blank"`)에 안내가 있는지
- 판정: 빈 링크는 자동 / 텍스트의 적절성은 AI
- axe: `link-name`, `identical-links-same-purpose`

#### 2.4.4 고정된 참조 위치 정보
- 기준: 전자출판문서 형식의 웹 페이지는 각 페이지로 이동할 수 있는 기능이 있어야 하고, 서식이나 플랫폼에 상관없이 참조 위치 정보를 일관되게 제공해야 한다.
- 코드에서 볼 것
  - 전자책·문서 뷰어 형태가 아니면 "해당 없음"으로 기록
- 판정: 수동
- axe: 직접 대응 없음

### 2.5 입력 방식

#### 2.5.1 단일 포인터 입력 지원
- 기준: 다중 포인터나 경로 기반 동작으로 작동하는 기능은 단일 포인터 입력으로도 사용할 수 있어야 한다.
- 코드에서 볼 것
  - 핀치 줌, 두 손가락 제스처, 스와이프·드래그로만 가능한 기능에 버튼 같은 대안이 있는지
- 판정: AI
- axe: 직접 대응 없음

#### 2.5.2 포인터 입력 취소
- 기준: 단일 포인터 입력으로 실행되는 기능은 취소할 수 있어야 한다.
- 코드에서 볼 것
  - `onMouseDown`, `onPointerDown`, `onTouchStart`에서 바로 실행되는 동작 (`onClick`/up 이벤트가 아닌 경우)
- 판정: AI
- axe: 직접 대응 없음

#### 2.5.3 레이블과 네임
- 기준: 텍스트(또는 텍스트 이미지)가 포함된 레이블이 있는 사용자 인터페이스 구성요소는, 네임에 시각적으로 표시되는 해당 텍스트를 포함해야 한다.
- 코드에서 볼 것
  - 화면에 "검색"이라고 보이는 버튼의 `aria-label`이 "submit"처럼 다른 경우
- 판정: AI
- axe: `label-content-name-mismatch`(실험)

#### 2.5.4 동작기반 작동
- 기준: 기기 동작(흔들기, 기울이기 등)으로 작동하는 기능은 그래픽 사용자 인터페이스로도 작동할 수 있어야 하고, 동작 기반 기능을 끌 수 있어야 한다.
- 코드에서 볼 것
  - `devicemotion`, `deviceorientation` 리스너
- 판정: AI
- axe: 직접 대응 없음

## 3. 이해의 용이성

### 3.1 가독성

#### 3.1.1 기본 언어 표시
- 기준: 주로 사용하는 언어를 명시한다.
- 코드에서 볼 것
  - `<html lang="ko">` (Next.js App Router는 `app/layout.tsx`)
- 판정: 자동
- axe: `html-has-lang`, `html-lang-valid`, `html-xml-lang-mismatch`, `valid-lang`(참고)

### 3.2 예측 가능성

#### 3.2.1 사용자 요구에 따른 실행
- 기준: 사용자가 의도하지 않은 기능(새 창, 초점 변화, 페이지 이동 등)은 실행되지 않아야 한다.
- 코드에서 볼 것
  - `<select onChange>`에서 바로 페이지를 이동하는 코드
  - 초점을 받는 순간 팝업이 뜨거나 화면이 바뀌는 코드
  - 사전 안내 없는 새 창(`window.open`, `target="_blank"`)
- 판정: AI
- axe: 직접 대응 없음

#### 3.2.2 찾기 쉬운 도움 정보
- 기준: 도움 정보가 제공되는 경우, 각 페이지에서 동일한 상대적인 순서로 접근할 수 있어야 한다.
- 코드에서 볼 것
  - 고객센터·도움말·챗봇 링크가 공통 레이아웃 컴포넌트에서 같은 위치·순서로 렌더링되는지
- 판정: AI / 수동
- axe: 직접 대응 없음

### 3.3 입력 도움

#### 3.3.1 오류 정정
- 기준: 입력 오류를 정정할 수 있는 방법을 제공한다.
- 코드에서 볼 것
  - 오류를 텍스트 메시지로 알리는지, `aria-invalid`, `aria-describedby`로 입력과 메시지가 연결되는지
  - 제출 실패 시 첫 오류 필드로 초점 이동
  - 오류 후에도 기존 입력값이 유지되는지
  - 오류 메시지가 `aria-live`/`role="alert"`로 전달되는지
- 판정: AI / 수동
- axe: 직접 대응 없음

#### 3.3.2 레이블 제공
- 기준: 사용자 입력에는 대응하는 레이블을 제공한다.
- 코드에서 볼 것
  - `<label htmlFor>` 연결, placeholder만 있고 레이블이 없는 입력
  - `aria-label`/`aria-labelledby`
  - 라디오·체크박스 그룹의 `fieldset`/`legend`
- 판정: 연결 여부는 자동 / 레이블 내용은 AI
- axe: `label`, `select-name`, `form-field-multiple-labels`, `label-title-only`

#### 3.3.3 접근 가능한 인증
- 기준: 인증 과정은 인지 기능 테스트(암기, 퍼즐 풀이 등)에만 의존하지 않거나, 대체 수단을 제공해야 한다.
- 코드에서 볼 것
  - 비밀번호·인증번호 입력에서 붙여넣기 차단(`onPaste` + `preventDefault`)
  - 비밀번호 관리자 자동 입력을 막는 설정
  - 문자 판독형 캡차만 제공하는지
- 판정: AI
- axe: 직접 대응 없음

#### 3.3.4 반복 입력 정보
- 기준: 반복되는 입력 정보는 자동 입력 또는 선택 입력할 수 있어야 한다.
- 코드에서 볼 것
  - 같은 절차 안에서 이미 입력한 정보를 다시 입력하게 하는지 (배송지 = 주문자 정보 등)
  - `autocomplete` 속성 사용
- 판정: AI
- axe: `autocomplete-valid`(참고)

## 4. 견고성

### 4.1 문법 준수

#### 4.1.1 마크업 오류 방지
- 기준: 마크업 언어의 요소는 열고 닫음, 중첩 관계, 속성 선언에 오류가 없어야 한다.
- 코드에서 볼 것
  - 같은 `id`의 중복 (반복 렌더링되는 컴포넌트에 고정 id → React는 `useId()` 사용)
  - 잘못된 중첩: `<button>` 안의 `<a>`, `<p>` 안의 `<div>` (React hydration 경고로도 드러남)
  - 같은 속성 중복 선언
  - `ul`/`ol` 바로 아래 `li`가 아닌 요소
- 판정: 자동 (검사 도구, 브라우저 콘솔 경고) / AI
- axe: `duplicate-id`, `duplicate-id-active`, `duplicate-id-aria`, `list`·`listitem`·`definition-list`·`dlitem`(참고)

### 4.2 웹 애플리케이션 접근성

#### 4.2.1 웹 애플리케이션 접근성 준수
- 기준: 콘텐츠에 포함된 웹 애플리케이션은 접근성이 있어야 한다.
- 코드에서 볼 것
  - 커스텀 컴포넌트의 역할과 상태: 드롭다운 `aria-expanded`, 탭 `role="tablist"/"tab"/"tabpanel"` + `aria-selected`, 토글 `aria-pressed`/`aria-checked`
  - 모달 `role="dialog"` + `aria-modal` + 제목 연결
  - 토스트·실시간 알림의 `aria-live`
  - 이름 없는 버튼, 잘못된 ARIA 속성 값
  - UI 라이브러리(Radix, shadcn/ui 등)의 기본 접근성을 커스터마이징하면서 깨뜨리지 않았는지
- 판정: 속성 오류는 자동 / 패턴 적합성은 AI / 실제 낭독은 수동 (스크린리더)
- axe: `aria-*` 규칙 전반, `button-name`, `input-button-name`, `nested-interactive`, `presentation-role-conflict`, `summary-name`
